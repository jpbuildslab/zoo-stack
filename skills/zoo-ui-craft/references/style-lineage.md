# Style Lineage

Resolve precedence for the visual decisions in scope. Follow the user's explicit direction for the
task. For choices it leaves open, establish which decisions the most recent applicable review or
maintained design guidance accepted. A newer accepted change to action placement can coexist with an
older accepted decision about content width. Use existing tokens, components, and screens to
understand the starting point. Their presence alone does not establish visual approval.
Check interaction, accessibility, permissions, and data against the current product contract and
implementation.

When references differ, use focused history, source, and review evidence to find the decision behind
the difference. Pin the example by path and revision or review artifact when that matters to the
comparison. Judge dimensions independently, such as hierarchy, density, typography, state treatment,
and responsive behavior.

- Preserve stable decisions the current task leaves in place.
- Carry an accepted evolution forward only in the dimensions and family it applies to.
- Preserve exceptions required by the target's task, content, accessibility, or behavior.
- For a substantial visual improvement against an unaccepted starting point, propose a focused
  direction using the real task, representative content and consequential states. Identify decisions
  that can vary and constraints the preview must preserve. Show the rendered direction for the
  requested review before carrying it into the working flow.
- Treat exploratory previews as proposals until accepted. An accepted prototype can establish
  presentation direction. The current product contract still governs live behavior and effects.

Record only the decisions that change the work. When the repository maintains pattern guidance,
record durable changes through its existing process after acceptance.
