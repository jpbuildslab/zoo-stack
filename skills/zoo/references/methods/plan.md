# Plan a repository change

1. Trace the requested outcome to the current user-facing path and the source that owns its behavior. Read the repository's applicable guidance and check instructions. Cite current behavior with source evidence and label inferred rationale.
2. Separate the required outcome, optional capabilities, and actual prerequisites. Keep a required native workflow usable with its current authority boundary. Identify which decisions or access are genuinely missing and which work can proceed on the current grant.
3. Describe the smallest coherent slice that reaches the outcome. Name the caller, important inputs, effects, failure and recovery behavior, affected owners, and the check that would prove the result. Compare alternatives only when the choice could change the design or evidence.
4. Say what can be checked from source and what needs an authorized local or hosted environment. A proposed action is a plan item. Preserve the user's current execution scope.
