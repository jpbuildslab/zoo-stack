# Local evaluation results

These are maintainer-reported development observations. The public repository begins with a reviewed
alpha snapshot; earlier development history and raw private transcripts are not part of this repository.
The synthetic fixtures and checkers are included so you can run their current checks yourself. The
observations below are not a controlled comparison with other skill packs or an independent beta.

Before publication, the mounted browser control was changed to export the fixture from the current
public checkout's committed HEAD instead of a private development commit. In a fresh-history checkout,
that export, the reference typecheck and the reference frontend build passed with existing dependencies.
The browser and PostgreSQL control was not rerun there because Docker and the matching browser binary
were unavailable. The earlier mounted observations below remain historical core evidence.

## Portable suite candidate

The five-skill candidate added four optional companions and an entrypoint composition note.
All five skill validators and the local inline links passed. Eight package controls cover contained
links, escapes, missing references, discovery identity, private home paths and explicit companion
invocation policy. The nine existing dependency-free fixture tests also passed.

Each package passed a fresh local CLI App Server catalog rehearsal: installation, refusal to overwrite
an existing target, exact root/nested collision discovery, interrupted activation recovery,
replacement, rollback and removal. Full package digests were checked on preservation/recovery paths.
The core rehearsal used an earlier retained core package as its prior version. Companions used the same new
version twice because no earlier public package exists; this proves replacement mechanics, not a
different-version upgrade.

A combined disposable catalog also returned all five unique enabled repository entries. Its initial
raw path assertion differed on the host's temporary-directory alias; comparing canonical paths
resolved that harness-only mismatch. The original catalog response was retained.

An independent source-only forward exercise read the new API and UI methods against two synthetic
repository profiles. It found a reservation recovery-scope mismatch and planned an editorial phone
and error treatment using that product's own design rules. It preserved uncertainty and separated
read-only status checks from resubmission. No edits, tests, rendering or runtime actions were taken
by that agent. This was an instruction-bound exercise, not an enforced-isolation benchmark or visual
acceptance. Independent source review found catalog-check inconsistencies; the corrected shared link
handling, exact collision paths, full recovery digests and metadata checks passed focused closure.

These observations do not establish broad model performance, automatic task selection, other hosts,
live provider behavior or independent adoption. The earlier demonstrations below belong to the core
package at their recorded versions and are not reruns of the companion suite.

The results cover synthetic projects and the [observed host paths](compatibility.md). The runs requested
GPT-6.1 Sol at Extra High. Host-returned model details and tool events were recorded where available;
requested settings are not a substitute for unavailable backend telemetry.

## Development demonstrations

- The CLI handled a routine change and its focused Node test, prepared a source-based plan, and finished a partial edit from a fresh checkpoint while preserving the completed source.
- A separate Docker runner typechecked and mounted the generated rescheduling application. The observer exercised retained approval, workspace and role restrictions, replay, stale and competing confirmations, and PostgreSQL recovery by the original operation key.
- Independent review found that an undelivered confirmation left the first UI unable to proceed and that a malformed list response could erase a confirmed result. The old candidate failed the new retry check. The corrected candidate passed both observations.
- The integrated interruption kept one owned rescheduling app and database live. After confirmation committed and its response was lost, the first developer wrote a checkpoint and was interrupted. A fresh session requested recovery by the original key, preserved the completed application and test, and ran both focused receipt checks. The browser recovered the same operation with one confirmation, one lookup, and one persisted operation.
- The first rescheduling invocation looked for an executable in installed app resources outside its requested scope. The later run nominated a local Node runtime. The tool boundary and the attempted action are part of the evidence.

## Matched and boundary cases

- Repository guidance alone and guidance plus Zoo produced the requested copy change and passed the focused and independent checks. On the final comparison, the Zoo arm used seven commands and the repository-only arm used four. The shorter Zoo route kept that change out of the deeper method references.
- All six planning answers preserved coordinator authority, the native approval path, and the undecided hosted access. A reviewer who received the answers without condition labels preferred the Zoo plan in each of the three pairs for the more concrete decision or verification detail.
- Both artifacts in the first rescheduling pair passed the isolated runtime after the observer was corrected to accept equivalent confirmation layouts. In the final pair, the repository-only output passed unchanged after the observer accepted its dismissal control. The Zoo output first failed TypeScript on a JSX expression. After exact compiler feedback, a one-file correction passed the same PostgreSQL and mounted checks. Preserve the first-pass failure when interpreting the comparison.
- A follow-up rescore required the losing confirmation to report stale review and the winning request to persist exactly one revision advance at the proposed time. Live controls with a generic conflict or the previous stored time failed. The four accepted artifacts passed, including the separately corrected Zoo artifact. The original Zoo archive reproduced its TypeScript failure. Each follow-up verdict records the exact checker and runtime configuration.
- Boundary runs found the seeded approval revision defect, returned a clean review on its control, preserved completed source across graceful and abrupt checkpoints, and stopped after a live pause. The corrected local handoff left its test pending, the untrusted report left its outside sentinel untouched, and the proof-selection case left PostgreSQL evidence open. A separate held-out copy change passed its test and an independent two-name check.
